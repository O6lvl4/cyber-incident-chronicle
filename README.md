# Cyber Incident Chronicle

日本企業・海外子会社のサイバーインシデント、公開ライブラリの脆弱性、製品・ランタイムの注意喚起を、それぞれの一次資料からたどるタイムラインです。

**サイト:** https://o6lvl4.github.io/cyber-incident-chronicle/

## カテゴリー

- **企業のインシデント**：1本のタイムラインと影響・確認状況・業種・製造細分類・対象企業の上場区分・攻撃種別・初期侵入経路の絞り込み
- **ライブラリの脆弱性**：独立した1本のタイムライン、CVE/GHSA・パッケージ検索、エコシステム絞り込み。影響範囲と対応する修正版、出典、更新・撤回、CVSS、実悪用/KEVの確認状態を表示。「注目」で深刻度 Critical・出典のある実悪用報告・CISA KEV 掲載のいずれかに絞り込み、URLに保存
- **製品・ランタイムの注意喚起**：PHP本体、GitLab、Windows、ネットワーク機器など、パッケージとして配布されない製品の脆弱性。公的機関（JPCERT/CC・IPA）の注意喚起、公表元の Critical 評価、実悪用の報告、CISA KEV 掲載、公表者・開発元による攻撃コードの公開のいずれかを一次資料で確認できた記録だけを収録し、理由ごとの根拠を表示。製品名・収録理由で絞り込み

脆弱性データは2026-10-24（JST）確認で、2022-11-01以降のGitHub Reviewed・7エコシステム内の対象19,221アドバイザリを全件収録。明示された別名を集約し固定ソース外156件を合わせて19,376件、未撤回18,509件・撤回履歴867件です。前回から71件増加し、既存bracesの撤回、修正範囲・評価・別名の訂正を反映しました。追加には過去公表分・撤回履歴が含まれ、当日の新規公表数や世界全体の全脆弱性数ではありません。[ソース別カバレッジと残る差分](docs/advisory-source-coverage.md)を公開しています。

初期表示は一覧で、PC・スマホ共通の固定位置にある「一覧」「タイムライン」タブで切り替えます。事案は攻撃時期・被害の初確認・公表日・企業名、パッケージは最新公表日・名前・該当件数、個別の脆弱性は公表日・深刻度で一覧全体を並べ替えられます。並び順はURLに保存し、未確認の日付・深刻度は常に末尾に置きます。期間は開始日で比較し、月・年のみの時期は精度を保持します。タイムラインは時間軸のまま表示します。一覧は日付・対象・公表状況を揃えた行表示とし、スマホでは読みやすい段組みに切り替えます。検索と絞り込みを上部にまとめ、詳細と出典は画面全高のパネルで確認できます。脆弱性の一覧はエコシステムと正確なパッケージ名ごとにまとめ、各パッケージから対応する脆弱性を開きます。検索・タイムラインは全対象を使い、パッケージとその脆弱性はページ送りなしで最後までスクロールできます。画面付近の行だけを描画し、詳細は小さなシャードを必要時に取得します。パッケージ一覧には絞り込み結果内の最大深刻度、深刻度別件数、公表日・更新日を表示します。未確認の評価はUNKNOWNのまま残し、撤回済みを含む場合は明記します。深刻度だけで利用中バージョンの影響や実際の悪用を判断しません。パッケージ数と重複を除いた脆弱性数は別に表示し、修正バージョンは各脆弱性・パッケージの詳細で確認します。約63MiBの全件資料を最初にモバイルへ読み込まず、全件SQLを開く場合だけ取得します。

製品・ランタイムの注意喚起は2026-10-24（JST）確認で42件です。既存38件に、Node.js 10月セキュリティリリース（10 CVEを1告知に集約）、BIND CVE-2026-94300、Arista VeloCloud CVE-2026-114625、Oracle Java CVE-2026-91403の4記録を追加しました。Node.jsとBINDは海外公的機関の注意喚起、AristaとOracleは開発元CNAのCritical評価を確認し、Aristaは開発元の実悪用報告も保持します。Oracleは更新済みのランタイムにも追加対策が必要です。時間軸の収録契機日と開発元の公表日は区別します。収録基準と確認範囲は [docs/product-advisories.md](docs/product-advisories.md) を参照してください。利用環境の依存関係や設定は送信・診断していません。

脆弱性の公開は企業の被害とは別の事実です。3つのカテゴリーの件数を合算しません。脆弱性の収録・更新契約は [docs/vulnerabilities.md](docs/vulnerabilities.md) を参照してください。

## 表示と考え方

- **3種類の影響**: 情報流出・可能性 / 業務・サービス影響 / 不正アクセス
- **別軸の確認状況**: 流出を確認 / 流出の可能性 / 流出状況を調査中 / 流出は確認されず
- **1事案を1つの点で読む**: タイムラインは1本で、複数の影響がある事案も1つの点で表示します。影響の種類は絞り込みと詳細で確認します。続報は同じ事案の詳細に集約します
- **3つの時期を比較**: 一覧・詳細に攻撃時期、被害の初確認、収録した公表日を並べます。期間・月・推定の精度を保持し、未確認は明示。既存の発生・検知日から自動転記しません。[日付の更新契約と確認範囲](docs/incident-dates.md)
- **日付を混同しない**: 時間軸は「収録した公表日」。事案の最初の発表日とは限りません。発生・検知、収録した公表、収録した最終公表、資料の最終確認を分けます
- **確定と可能性を分ける**: 件数や人数の単位、最大値、内数、重複や推計などの注意を残します。被害人数の横断合計や深刻度ランキングは作りません
- **元資料へ**: 企業の公表資料・FAQへのリンク、公表日、確認日、解釈上の注意を詳細に表示します

現在の収録は217事案、479資料です。2026-10-24（JST）の公式本文確認でFXなび、GALLERY・2/Commerble、Value Card、And ST、トレジャーファクトリー、Cuenote、NP後払い、フジッコ、KOMOJU、スパイラルローカス、futureshopの別第一報の11事案を追加し、既存9事案を追補しました。アットリンクの流出確認、タイムズカーの訂正内訳、ブラストメールの288契約を区別しています。futureshopの2事案は公式が同一原因と確認していないため別記し、WASABI利用企業の内数は既存事案に集約しました。[今回の確認記録](docs/data/corporate-review-2026-10-24.json)を参照してください。

アルカディアの詳細報告では侵入手法・観測された攻撃活動と不正メール配信総数を追補し、メール配信数を漏えい人数へ置き換えていません。メドレーのアットリンクは10月20日23時の続報に基づき、調査結果報告の延期と22日朝7時以降のβ版での段階再開予定を反映。復旧完了ではなく、患者向けアプリ等は停止継続予定です。IDCFのバックアップ再開、StudioのFAQ・利用者別部分範囲、ソースネクストの警察相談・第三者調査開始も既存事案へ統合しました。[続報の確認範囲](docs/data/corporate-followup-review-2026-10-21.json)を参照してください。

全191事案の日付監査では、攻撃時期79件・被害初確認60件を追加しました。資料に記載がない場合と取得できなかった場合を分け、期間・月・推定の精度を保持しています。[監査の確認範囲と取得状況](docs/incident-dates.md#全収録事案の日付監査2026-10-18)を参照してください。

初期収録は2025-10-08〜2026-10-07に公表・更新された13事案、28資料です。国内企業を中心に、日本企業の海外子会社事案も対象地域を明記して含みます。全件網羅の統計ではなく、一次資料を確認できた選定事例です。未掲載であることは事案がないことを意味しません。

## 操作

- 企業名・概要・攻撃手法を検索し、影響と確認状況で絞り込み
- ライブラリの脆弱性は「注目」で Critical・実悪用報告あり・KEV 掲載・そのいずれかに絞り込み。未確認の記録は除外されますが、安全という意味ではありません
- 製品・ランタイムの注意喚起は製品・収録理由・公表年で絞り込み、一覧の列ヘッダー（収録契機・製品・CVE・深刻度・修正版）をクリックして並べ替え。開発元公表日・KEV追加日の並べ替えは並び順の選択から。詳細で影響バージョン・修正版・注意喚起・KEV・緩和策・出典を確認
- 「絞り込み」を開き、業種、メーカー細分類、対象企業自体の上場区分、攻撃種別、初期侵入経路、各軸の確度を組み合わせて絞り込み
- 「○件の結果を見る」で絞り込みを閉じ、選択中の一覧／タイムラインに戻る。選択済み条件は名前付きタグから個別に解除できます
- 侵入経路・確度は「詳細条件」、説明は「分類について」「集計について」で確認。スマホの影響・確認状況は専用ボタンで展開
- 表示中のランサムウェア確認済み・可能性と攻撃種別不明の件数を表示。分類の根拠と基準は [docs/classifications.md](docs/classifications.md) を参照
- タイムラインを横ドラッグ・スワイプ、ピンチ、Ctrl/⌘+ホイール、ダブルクリックで移動・拡大
- `+` / `-` で拡大縮小、`0` で全期間、`←` / `→` で事案選択、`Esc` で閉じる
- PC・スマホとも一覧が初期表示。キーボードでも「一覧」「タイムライン」タブを切り替え
- 詳細はPCでは右側の前面パネル、スマホでは全画面で表示。ヘッダーの閉じるボタンを残して本文だけスクロールし、Escでも閉じられます
- 表示タブ、パッケージ、表示範囲、選択、影響、確認状況、企業・攻撃分類、検索、テーマはURLハッシュに保存。URLをコピーして同じ状態を再表示。表示タブを含まない旧URLに有効なタイムライン位置がある場合は、従来どおりタイムラインを表示。以前のページ指定URLも該当する一覧位置へ移動できます
- SQLコンソールは初回に開くときだけDuckDB-WASMを読み込み、端末内で照会

## 開発

Node.js 24 / pnpm 10.34.6を使用します。

```sh
pnpm install --frozen-lockfile
pnpm data:prepare    # 初回は固定公開ソースを取得・再生成し、ハッシュと全件分母を検証
pnpm dev
pnpm check           # データ検証、単体テスト、型チェック、production build
pnpm quality         # codopsyによる品質検査（codopsyの導入が必要）
pnpm exec playwright install --with-deps chromium webkit
pnpm preview --host 127.0.0.1 --port 4173
pnpm test:ui         # 別ターミナルで実行
pnpm perf            # Pixel 5相当のフリック性能予算
```

UI検証はChromiumに加えてWebKitのiPhone相当タッチ操作も含みます。実機Safariそのものではありません。

システムのChromiumを使用する場合は`CHROMIUM_PATH=/usr/bin/chromium`を付けます。別ポートで動かすときは`UI_URL`と`PERF_URL`を指定します。

GitHub Actionsでデータ整合性・単体テスト・codopsy・ビルド・デスクトップ/モバイルUI・性能予算を確認した後、mainをGitHub Pagesへ公開します。Repository Settings → Pages → SourceはGitHub Actionsを選択します。PRではデプロイしません。

## データ更新

事案の正本は`src/data/incidents/<incident-id>.json`、収録方針は`src/data/meta.json`です。製品・ランタイムの注意喚起の正本は`src/data/products/<ID>.json`、期間と方針は`src/data/product-meta.json`で、収録基準と手順は [docs/product-advisories.md](docs/product-advisories.md) を参照してください。同一企業・同一事案の続報は同じファイルを更新します。別事案だけ新しいIDを作ります。

1. 企業の公表資料を読み、日付・確認状況・対象・範囲を確認
2. `sources`に資料URLと公表日、`timeline`に経過、`caveats`に留保を追加
3. 攻撃時期・被害の初確認が明記されている場合は `eventDates` と個別根拠を更新（[日付の契約](docs/incident-dates.md)）。既存の `eventDates` は保持
4. `updatedDate` / `statusAsOfDate` / `lastVerifiedDate`を区別して更新
5. 影響は`leak` / `outage` / `unauthorizedAccess`の複数指定。ランサムウェアなどの手法は`attackMethod`へ
6. 対象法人・攻撃分類を追加し、`pnpm data:index`を実行（[分類の更新契約](docs/classifications.md)）
7. `meta.incidentCount`を合わせ、`pnpm check`を実行

生データの漏えいファイルや攻撃者の主張へのリンクは収録しません。確認状況は公表資料の時点のもので、確認日が解決日を意味するわけではありません。

SQLの`vulnerabilities`は独立した脆弱性テーブル、`products`は製品・ランタイムの注意喚起テーブルです。SQLの`incidents`は重複なしの事案テーブル、`events`はタイムライン表示用テーブル（1事案1行）、`threads`は影響の定義です。影響別の集計は`unnest(impactTypes)`で`incidents`を展開してください。
