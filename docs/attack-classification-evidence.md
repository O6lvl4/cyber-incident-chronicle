# 攻撃・事象の種類と初期侵入経路：分類根拠

## 対象と日付

2026-10-08に、既存95事案の記述を一件ずつ読み、分類値・確度・根拠URL・日本語の留保を追加した。既存の事案JSON、人数・件数、日付、漏えい確度は変更していない。

- 分類は明示的に保存した編集データ。実行時のキーワード推定ではない
- `reviewedDate` は分類を検討した日。公表日、発生日、原資料の更新日、全ソースの再取得日とは異なる
- 各事案の情報時点は元レコードの `statusAsOfDate` / `updatedDate` に従う。2026-10-08以後を含む継続的な網羅調査を意味しない
- 全95件について既存の出典付き記述を確認し、下記の重要な境界例は公式ページ・PDF本文も直接確認した。95件すべての全URLを新たに取得したという意味ではない
- `sourceUrls` はその分類判断が参照する、元事案にも収録された公式資料。`note` に適用範囲と不明点を残す

## 独立した二軸

`attackKind` は攻撃・事象の代表的な種類、`initialAccess` は公表資料で示された侵入の方法・経路。双方に独立した `Status` を持たせる。

- `confirmed`：根拠資料でその事実・手法が確認済みと説明されている
- `possible`：会社・調査機関の推定、可能性、可能性が高いという説明
- `unknown`：分類できる具体的な情報が不明または非公表。侵害や被害がなかったという意味ではない
- `notApplicable`：外部攻撃ではない不具合等で、攻撃の種類・入口という概念が適用されない

元の `attackMethod.status` を二軸へそのまま複写しない。同じ説明に「ランサムウェアは確認」「侵入経路は推定」が併記される場合、それぞれに確度を付ける。漏えい確度とも混ぜない。

### 種類の境界

- `ransomware`：会社がランサムウェアと説明したもの、または暗号化と復旧のための身代金要求という具体的挙動を確認したもの。後者の編集判断はソーゴーの注記に明示した。停止・漏えい・身代金要求単独では付けない
- `malware`：ランサムウェア以外または種別未特定の不正プログラム・バックドア。感染後のフィッシング送信を初期侵入の証拠にしない
- `webTampering`：決済アプリ・Webページ・埋め込みスクリプトの改ざんが明示されたもの。Webシステムへの不正アクセス全般ではない
- `credentialAbuse`：ID・パスワード・アクセスキー・アカウントの不正利用。身代金要求を伴っても、ノーウェアランサムや感染否定をランサムウェアに変えない
- `insider`：職員・元職員・委託先要員の業務上アクセスによる不正持ち出し等。盗まれた認証情報を使う外部攻撃と区別する
- `misconfiguration`：設定不備による非攻撃の露出事象。侵入経路は `notApplicable`。設定ミスを悪用する攻撃では初期侵入軸に設定不備を置く
- `other`：SQLインジェクション、XXE、ランサムウェアとは明記されない暗号化、問い合わせフォームの悪用など、既知だが上記種類に収まらない具体的手法
- 不正アクセスだけが確認された場合は `unknown`。入口の脆弱性が判明していても、攻撃プログラム等の種類を埋める必要はない

一事案一値の代表分類であり、複数段階やすべての手法の網羅タグではない。ランサムウェア実行と認証情報悪用が併存する場合は前者を種類、後者を入口に置く。Web決済改ざんは汎用的なマルウェア分類より具体的な改ざんとして扱う。例外・複数システムの範囲は注記を必ず読む。

### 入口の境界

- 明示された脆弱性悪用は `vulnerability`。VPN等の製品名があるだけでは脆弱性悪用としない
- VPN・ファイアウォール・リモートアクセス機器経由だけが判明している場合は `networkDevice`。認証・脆弱性・設定の具体的機序を補わない
- `credentials` は認証情報を用いた侵入。認証情報が盗まれた方法まで判明しているという意味ではない
- `phishing` は被害企業側の侵入契機として確認されたもの。侵害後に顧客へ送ったフィッシングは含めない
- テスト環境・関係会社経由、フォーム機能悪用など、他の選択肢に当てはまらない明示的な経路は `other`。そこから別の機序を推定しない
- 複数システム・別指標をまとめた事案では、一部のアカウント不正利用を全体の初期原因に転用しない

## 更新時の注意

1. 元の事案IDに対応する分類を必ず1件保持し、廃止・統合・追加時はID集合を照合する
2. 事案を追加しただけで具体的な手法を推定しない。分類できない軸は明示的な `unknown` とする
3. 新しい根拠で確度が変わったときだけ該当軸を更新し、注記・根拠URL・分類確認日を見直す
4. 負の証拠（感染否定・関連未確認）と、確定／推定／非公表の区別を残す
5. 件数は選定した95事案内の集計。国内企業全体の発生率・攻撃傾向の統計ではない
