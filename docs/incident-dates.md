# 企業事案の日付の読み方・更新契約

一覧と詳細では「攻撃があったとされる時期」「被害を最初に確認した日」「公表日（収録資料の起点）」を並べます。時間軸・既定の公表日順は引き続き `announcementDate` を使用し、収録起点を初報とは断定しません。

## 意味を混同しない

- 攻撃時期は公式調査で確認されたアクセス・攻撃の時期。初期侵入日を特定したとは限りません
- 被害の初確認は、公表資料が最初の確認日と結び付けて示す日。侵入の検知、異常の検知、流出のおそれの把握、公表日から推測しません。情報流出・業務影響など確認した被害の種類を `note` に残します
- 既存 `occurredDate` / `occurredDateLabel`、一部記録の `detectedDate`、経過、収録公表日を保持します。これらから自動で新項目へ転記しません
- 流出対象データの作成・注文・在籍期間は攻撃期間ではありません
- `未確認・不明` はまだ新項目を検証できていない記録。`未公表・不明` は確認した資料から日付を特定できなかった記録。どちらも攻撃や被害がなかったという意味ではありません

## 正本と互換性

正本 `src/data/incidents/<id>.json` に任意の `eventDates.attack` / `eventDates.damageConfirmed` を追加します。欠落した既存事案を除外せず、全件を表示します。脆弱性のデータ・日付の意味は変えません。

各項目は `precision`, `label`, `note`, `sourceUrl`, `reviewedDate` を持ちます。

- `day`: 日が判明。`startDate` が必須、`endDate` は付けません
- `month` / `year`: 月・年まで判明。表示用 `label` に原資料の精度を保ち、便宜上の1日へ変換しません
- `period`: 期間。`startDate` を持ち、終了が判明した場合だけ `endDate` を記入。`label` に「以降」や別々の期間を明記します。複数の期間の場合、境界値の間すべてで攻撃が継続したとは解釈しません
- `approximate`: 推定時期。元資料の表現を `label` に保存し、画面でも「推定」を表示します
- `unknown` / `notApplicable`: 不明／非該当。境界日を入れず、一次資料に基づく理由を `note` に残します。単なる未調査は項目を省略します

`sourceUrl` は同じ事案の `sources` に含め、根拠資料へのリンクと個別確認日を詳細に表示します。複数資料にまたがる根拠は `note` に資料と事実の対応を残します。全体の確認日や件数を便宜上更新しません。

## 一覧の並べ替え

攻撃時期・被害の初確認・公表日をそれぞれ新しい順／古い順で選べます。既定は公表日の新しい順で、企業名順と既存URLも保持します。選択は `sort=attack-asc/attack-desc/damage-asc/damage-desc` としてURLに保存され、検索・絞り込み後の全件に適用されます。タイムラインは公表日順のままです。

- 期間は `startDate` で比較。終了日は並び替えに使いません
- 月・年は厳密な `YYYY年M月` / `YYYY-MM` / `YYYY年` / `YYYY` ラベル（末尾の「日不明」「月日不明」の注記を許容）から年月だけを比較。内部の比較用タプルでは欠けた要素を0とし、日付を生成・保存・表示しません。同じ月・年の具体的な日付より古い側に置く規則で、実際の前後関係を断定しません
- 推定時期は明示された `startDate` があればそれを比較し、推定表示を保持します。季節など文章だけの時期を推測変換しません
- 未確認・不明・非該当・比較可能な時期がない記録は昇順／降順とも末尾。同じ比較値は事案IDの昇順で安定化します
- 発生・検知・公表日による代用はしません。新項目の一次資料確認が済んでいない事案も除外されません
